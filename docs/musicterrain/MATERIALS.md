# Preview materials

`crates/musicterrain/src/materials.rs` defines 54 stable texture-array
layers for the MusicTerrain preview. The artwork generated by this module is
original procedural pixel art. No Minecraft image is bundled, downloaded or
written into the repository by the loader.

The enum uses `#[repr(u16)]`. `Material::ALL` fixes the atlas order;
`layer()` returns that index, `tint()` returns the RGB vertex multiplier and
`translucent()` returns true only for water. Leaves, grass and flowers use alpha
cutout rather than being classified as blended surfaces. The scene mesher owns
face materials and geometry; the renderer owns the texture array and its passes.

`TextureAtlas::load(None)` returns all 54 fallback layers. Each layer is
32 × 32 RGBA8 with an original 16 × 16 pixel pattern enlarged by nearest sampling.
The fallback is deterministic and visually distinguishes soil, stone, water,
bark, wood rings, vegetation, flowers, snow and minerals. It replaces the former
single pale texture; it is not a claim to contain Minecraft's proprietary art.

## Loading a local pack

`TextureAtlas::load(Some(root))` searches these locations in order:

1. `root/assets/minecraft/textures/block`
2. `root/minecraft/textures/block`
3. `root/textures/block`
4. `root/block`
5. `root` itself

This accepts a resource-pack root, a prepared Horizon resource root, an assets
root, a textures root, or the block-texture directory directly. A candidate must
contain at least one supported filename. A nonexistent root, a file in place of
a root, or a directory containing no recognised block texture produces an error.
Zip packs are not opened by this module; select an extracted resource directory.
Older tall-grass names `tall_grass_bottom.png` and `grass.png` are accepted if
`short_grass.png` is absent.

Present images are decoded through Horizon's production
`horizon_client_render::hud::decode_bytes`, which is also called by `hud::decode`.
The loader reads each PNG once, validates that same byte buffer, then passes it
to the decoder. All layers are nearest-resized to 32 × 32. Square textures and
integral horizontal or vertical strips are accepted; a strip uses its first
square frame. Playback of texture animations and custom `.mcmeta` frame grids
are not implemented here. This keeps the music preview's material sampling
stable while its geometry changes.

Missing material PNGs retain their fallback art. A present corrupt, oversized or
unsupported PNG produces an error instead of silently claiming to have loaded
the resource pack. `TextureAtlas` reports `loaded`, `fallback`, `missing` and
`grass_overlay_loaded` so the UI can state exactly which resources were used.
`loaded` counts material layers; the optional grass overlay is not an extra layer.
The loader itself does not log or retain the user's root path. Errors name the
texture file and reason without including a complete user path.

## Tints and alpha

Grass tops, tall grass and oak leaves retain native grayscale texels and receive
their green vertex tint during rendering. Grass sides receive white vertex tint.
When `grass_block_side_overlay.png` is present alongside the native side texture,
the loader multiplies the overlay by the grass tint, then composites it with
straight-alpha arithmetic onto the side texture. Transparent overlay regions
leave the brown dirt unchanged. If the overlay is absent, the supplied native
side texture is retained as-is; the fallback side already contains a green edge.

Plant and leaf alpha values are preserved. Procedural leaves include transparent
holes, and procedural grass/flowers include transparent backgrounds. Procedural
water uses alpha 155. Loaded water alpha is capped at 160, preserving any more
transparent pixels; this provides a visible blended surface even when the source
water PNG is fully opaque. Water's RGB uses a blue vertex tint in both paths.

## Budgets and tests

Only fixed material filenames are resolved beneath the selected texture root.
Input images must be regular files of 33 bytes to 16 MiB. The PNG signature and
IHDR are checked before decoding; dimensions must be positive, at most 2048 per
edge and at most four megapixels. Decoded dimensions and the RGBA byte count are
checked before resizing. These are explicit preview import limits; high-resolution
or very long animated strips outside them are rejected with an error.

`crates/musicterrain/tests/materials.rs` constructs original PNGs with a small
test-only stored-zlib encoder and CRC checksums, requiring no added dependency.
Six tests cover stable/distinct layers, cutout/blended alpha, real PNG decoding
through the supported root layouts, nearest first-frame sampling, grass-overlay
composition, corrupt inputs, invalid roots and byte/dimension budgets.

```sh
cargo test -p musicterrain --no-default-features --features native --test materials
```

All six material tests passed in the consolidated native run. The complete
MusicTerrain suite has 60 passing tests; all-target Clippy and formatting passed.
A real renderer smoke additionally loaded a test-owned local PNG, reported one
local layer plus sixteen original fallbacks, and produced a GPU readback PNG.
No Minecraft asset was used for these tests. See TEST_REPORT.md and
verification/scene/ for the actual command output.
